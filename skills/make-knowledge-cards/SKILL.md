# Make Knowledge Cards

## Overview

将长文本文章拆解为结构化知识卡片，帮助用户快速掌握核心知识点并通过自测加深记忆。

## Input Handling

接受两种输入来源：

1. **直接粘贴的文本**：用户在对话中粘贴的文章或段落。
2. **本地文件**：用户提供的 `.md` 或 `.txt` 文件路径。使用 `Read` 工具读取文件内容。

如果输入是其他格式（PDF、网页链接等），明确告知用户当前仅支持 Markdown/TXT 文件和直接粘贴的文本，建议用户先将内容复制为纯文本后再使用。

## Workflow

按以下顺序执行：

### 1. 通读全文，识别核心知识点

- 完整阅读文章，标记出所有关键概念、定义、原理、结论和重要事实。
- 优先保留：定义性知识、因果关系、可操作方法、易错点、重要数据。
- 跳过：过渡性语句、重复表述、举例说明中的冗余细节、纯抒情或铺垫内容。

### 2. 去重与合并

- 将表达同一知识点的多处内容合并为一条。
- 如果两个知识点高度相关且可以在一张卡片中讲清楚，合并；否则分开。
- 判断标准：一张卡片只讲一个独立的、可单独记忆的知识点。

### 3. 确定卡片数量

- 目标输出 **5～8 张**卡片。
- **信息不足时不要强行凑数**：如果全文只包含 3 个真正重要的知识点，就只输出 3 张，并在开头说明"本文核心知识点较少，共提取 N 张卡片"。
- 如果文章很长且核心知识点超过 8 个，选取最重要的 8 个，不要全部堆砌。

### 4. 为每张卡片撰写内容

每张卡片必须包含以下四个部分：

- **标题**：简洁概括这个知识点，控制在 15 字以内。
- **核心知识**：一句话陈述这个知识点是什么，是卡片的主干。
- **简明解释**：用 2～4 句话展开说明，帮助理解。可以补充原理、背景或适用条件。
- **例子或自测问题**：二选一——
  - 例子：用一个具体场景或类比说明这个知识怎么用。
  - 自测问题：提出一个可以用这个知识点回答的问题，引导用户主动回忆。

### 5. 输出格式

使用以下 Markdown 格式输出每张卡片：

```
### 卡片 N：标题

**核心知识：** 一句话陈述。

**解释：**
2～4 句话的简明解释。

**例子 / 自测：**
（例子或自测问题，二选一）
```

卡片之间用空行分隔。

## Quality Rules

严格遵守以下规则：

1. **不编造**：所有内容必须来自原文。如果原文没有足够信息解释某个概念，不要自行补充外部知识，宁可少做一张卡片。
2. **不重复**：每张卡片讲的内容必须互不重叠。
3. **忠于原意**：概括时不能改变原文的结论或立场。
4. **语言简洁**：解释部分用短句，避免学术化堆砌。
5. **数量诚实**：宁可少而精，不要多而水。

## What This Skill Does NOT Do

- 不抓取网页内容（用户需自行粘贴文本或提供本地文件）
- 不解析 PDF 文件
- 不导出为 Anki 格式或其他闪卡软件格式
- 不生成图片或可视化卡片界面
